# راهنمای Monn Studio و موتور بازی Monn 1.4.2

Monn Studio محیط گرافیکی فارسی برای طراحی بازی داستانی و دوبعدی است. منبع پروژه با زبان مستقل MONN ذخیره می‌شود و همان پروژه از طریق موتور پایتون یا خروجی HTML5 اجرا می‌شود.

## امکانات نسخه ۱.۴.۲

- نقشهٔ داستان با صحنه‌ها و مسیرهای انتخاب
- ویرایشگر بصری چندشرطی برای شرط‌ها و رویدادها
- پیش‌نمایش بازی درون Studio بدون دانلود خروجی
- شخصیت با تصویر، ویدیوی MP4/WebM، صدای گفتار، حالت‌های چهره و مدل GLB/GLTF
- کلیپ ویدیویی کوتاه یا بلند با زمان شروع و پایان اختیاری
- قواعد ثابت پرسش/پاسخ و اتصال اختیاری NPC به API سازگار با OpenAI
- جهان دوبعدی با نقشه، اشیا، حرکت WASD/کلیدهای جهت، برخورد مستطیلی و Sprite Sheet
- طراح رابط کشیدنی با متن، دکمه، تصویر، پنل، کادر ورود نام و مکان؛ جابه‌جایی و تغییر اندازه روی بوم
- تایم‌لاین چندلایهٔ صحنه برای ویدیو، صدا و انیمیشن؛ تنظیم شروع، مدت، نقطهٔ ورود و خروج کلیپ
- اجرای کلیپ‌های تایم‌لاین در خروجی وب و انیمیشن سادهٔ موقعیت، شفافیت و مقیاس عناصر رابط
- موسیقی، افکت دکمه، صدای دیالوگ و صفحهٔ منابع/مجوزها
- ذخیرهٔ خودکار پروژه در IndexedDB و منبع بومی MONN

تایم‌لاین فعلی برای زمان‌بندی کلیپ‌های ویدیو و صدا و انیمیشن سادهٔ موقعیت، شفافیت و مقیاس عناصر رابط طراحی شده است؛ ادیتور keyframe پیشرفته و انیمیشن استخوانی هنوز آماده نیستند. محدودهٔ فعلی موتور دوبعدی پایه و برخورد AABB است؛ فیزیک پیشرفته، انیمیشن استخوانی، ویرایشگر tilemap حرفه‌ای و چندنفره آنلاین هنوز آماده نیستند. مدل‌های GLB/GLTF با model-viewer نمایش داده می‌شوند و دریافت این کتابخانه از CDN به اینترنت نیاز دارد.

## شروع سریع با Monn Studio

```powershell
py -m pip install -e .
monn-studio
```

یا `monn --studio` را اجرا کن. مرورگر به نشانی محلی `http://127.0.0.1:8765` باز می‌شود. سرور به‌صورت پیش‌فرض فقط روی رایانهٔ خودت گوش می‌دهد.

### گردش کار ساخت بازی

1. از پنل صحنه‌ها، بخش‌های داستان را بساز و کارت‌ها را روی نقشه مرتب کن.
2. در هر انتخاب، «اتصال روی نقشه» را بزن و صحنهٔ مقصد را انتخاب کن.
3. روایت، تصویر، ویدیو، موسیقی، مدل سه‌بعدی و صدای صحنه را تنظیم کن.
4. شخصیت بساز؛ برایش پرتره، ویدیو، حالت‌های چهره، صدا یا مدل سه‌بعدی انتخاب کن.
5. از ویرایشگر منطق، شرط‌ها و رویدادهای انتخاب را اضافه کن.
6. از تب جهان 2D، اشیا، موقعیت، اندازه، برخورد و فریم‌های Sprite Sheet را تنظیم کن.
7. از «طراح کشیدنی رابط» عناصر را روی بوم قرار بده و اندازه، رنگ، متن و مقصد آن‌ها را تنظیم کن؛ از «رابط و منو» هم صفحه‌های شروع، تنظیمات و پایان را مدیریت کن.
8. در «تایم‌لاین»، لایهٔ ویدیو، صدا یا انیمیشن بساز و زمان‌بندی کلیپ‌ها و نقطه‌های ورود و خروج را تنظیم کن.
9. «پیش‌نمایش زنده» را بزن تا بازی درون Studio اجرا شود.
10. «ذخیرهٔ MONN» و «ساخت بازی وب» را برای ذخیرهٔ منبع و خروجی HTML انتخاب کن.

پروژه‌های بزرگ و رسانه‌های جاسازی‌شده در IndexedDB نگهداری می‌شوند. برای پشتیبان‌گیری، فایل MONN را هم ذخیره کن؛ پاک‌کردن داده‌های مرورگر ممکن است ذخیرهٔ محلی را از بین ببرد.

## زبان بومی MONN نسخه ۲

فایل .monn از دستورهای خود زبان تشکیل می‌شود: `بازی`، `بازیکن`، `شخصیت`، `مأموریت`، `صحنه`، `انتخاب`، `شرط`، `اثر`، `جهان` و `رابط`. نمونهٔ کامل در `examples/studio_demo.monn` است.

```text
# MONN Game Language · نسخه ۲
بازی "ماجراجویی من"
شناسه "my-game"
شروع "entrance"

بازیکن {
  جان = 100
  حداکثر_جان = 100
  ویژگی "سکه" = 0
  کوله_پشتی = []
}

صحنه "entrance" "ورودی" {
  روایت = "به ماجراجویی خوش آمدی."
  انتخاب "رفتن به حیاط" -> "yard" {
    شناسه = "go_yard"
    شرط "stat" "سکه" >= 0
    اثر "stat" "سکه" add 1
  }
}

صحنه "yard" "حیاط" {
  روایت = "به حیاط رسیدی."
}
```

اجرا و ساخت وب:

```powershell
monn examples/studio_demo.monn --game
monn examples/studio_demo.monn --game --web --output dist/index.html
```

فایل‌های قدیمی MONN که از بلوک JSON نسخهٔ ۱ استفاده می‌کردند همچنان برای سازگاری خوانده می‌شوند؛ ذخیرهٔ جدید Studio از دستورهای بومی نسخهٔ ۲ استفاده می‌کند. فرمت JSON با پسوند .mongame.json نیز همچنان برای پروژه‌های قدیمی پشتیبانی می‌شود.

## ویدیو، صدا و مدل سه‌بعدی

- فایل‌های تصویر، صدا، MP4، WebM و GLB/GLTF از کتابخانه وارد می‌شوند.
- سقف هر فایل واردشده از رابط فعلی ۳۲ مگابایت است؛ سقف درخواست ساخت محلی ۴۸ مگابایت است.
- ویدیو می‌تواند کوتاه یا بلند باشد؛ برای صحنه، شخصیت و دیالوگ می‌توان زمان شروع و پایان کلیپ را تعیین کرد. پشتیبانی codec به مرورگر بستگی دارد.
- مدل‌های GLB/GLTF در صحنه، شخصیت یا جهان دوبعدی به شکل viewer قابل مشاهده‌اند؛ این قابلیت موتور فیزیک سه‌بعدی نیست.
- خروجی HTML رسانه‌های جاسازی‌شده را همراه خود دارد؛ برای رسانه‌های بزرگ‌تر می‌توان از مسیر نسبی یا میزبانی HTTPS استفاده کرد.

## شخصیت‌های هوشمند

برای شخصیت، دستور رفتاری و قواعد ثابت با قالب «عبارت پرسش => پاسخ» تعریف کن. قواعد ثابت بدون اینترنت و API کار می‌کنند. برای پاسخ آزاد، بازیکن هنگام اجرای بازی کلید API را وارد می‌کند؛ کلید در پروژه ذخیره نمی‌شود. سرویس باید endpoint سازگار با OpenAI و CORS مجاز داشته باشد. برای انتشار عمومی از proxy امن سمت سرور استفاده کن و کلید محرمانه را در HTML قرار نده.

## جهان دوبعدی و برخورد

ابعاد نقشه، پس‌زمینه، بازیکن و اشیای Sprite قابل تنظیم‌اند. هر شیء می‌تواند solid باشد. حرکت بازیکن با WASD یا کلیدهای جهت انجام می‌شود و برخورد با روش مستطیلی AABB محاسبه می‌شود. برای Sprite Sheet افقی، مقدارهای `frames`، `fps`، `frame_width` و `frame_height` را تعیین کن. این نسخه هنوز فیزیک کامل، tilemap پیشرفته یا انیمیشن استخوانی ندارد.

## اعتباردهی و مجوزها

برای هر دارایی نام پدیدآورنده، منبع و مجوز را در کتابخانه ثبت کن؛ خروجی بازی صفحهٔ «منابع و مجوزها» دارد. کد مخزن تحت MIT است و اعلان حق نشر و مجوز باید هنگام بازنشر کد حفظ شود. مجوز تصویر، صدا، ویدیو و مدل واردشده جداست؛ هنگام کپی یا ویرایش آثار دیگران نام و منبع را ذکر کن و فقط در محدودهٔ مجوز عمل کن. راهنمای کامل در `docs/COPYRIGHT_AND_ATTRIBUTION_FA.md` است.

## پشتیبانی از کلیدها و API فارسی

برای ساخت پروژه لازم نیست نام فیلدهای JSON را انگلیسی بنویسی. موتور معادل‌های فارسی را نیز می‌شناسد؛ نمونه کامل در `examples/story_persian.mongame.json` قرار دارد.

نمونه کوتاه:

```json
{
  "اطلاعات": {
    "شناسه": "بازی-من",
    "عنوان": "ماجراجویی من",
    "صحنه_شروع": "آغاز"
  },
  "بازیکن": {
    "جان": 100,
    "حداکثر_جان": 100,
    "ویژگی‌ها": {"سکه": 0},
    "کوله‌پشتی": []
  },
  "صحنه‌ها": [
    {
      "شناسه": "آغاز",
      "عنوان": "اتاق آغاز",
      "روایت": "داستان از اینجا شروع می‌شود.",
      "انتخاب‌ها": [
        {
          "متن": "رفتن به جنگل",
          "مقصد": "جنگل",
          "شرط‌ها": [],

        }
      ]
    }

}
```

در کلیدهای فارسی، این معادل‌ها پشتیبانی می‌شوند: «ویژگی»، «جان»، «پرچم»، «آیتم»، «مأموریت»، «دفترچه»، «افزودن»، «تنظیم»، «کاهش»، «مصرف»، «شروع»، «تکمیل» و «شکست». عملگرهای ریاضی را می‌توانی با نمادهای معمول یا واژه‌های «برابر»، «نابرابر»، «بزرگتر»، «کوچکتر»، «بزرگتر_مساوی» و «کوچکتر_مساوی» بنویسی.

API پایتون نیز نام‌های فارسی دارد:

```python
from monn import موتور_بازی, پروژه_بازی, بارگذاری_بازی, ساخت_بازی_وب

پروژه = بارگذاری_بازی("examples/story_persian.mongame.json")
بازی = موتور_بازی(پروژه)
print(بازی.صحنه)
print(بازی.انتخاب_های_در_دسترس())
بازی.انتخاب("برداشتن_نقشه")
print(بازی.وضعیت())
بازی.ذخیره("ذخیره.json")
```

## ۵. انتخاب‌ها و شرط‌ها

هر انتخاب دارای متن و مقصد است. مقصد را با شناسه صحنه بنویس. مقدار null به معنی پایان مسیر است.

\`\`\`json
{
  "id": "open_door",
  "text": "بازکردن در",
  "target": "secret_room",
  "conditions": [
    {"type": "item", "name": "کلید", "op": ">=", "value": 1},
    {"type": "stat", "name": "سکه", "op": ">=", "value": 5}
  ],
  "effects": []
}
\`\`\`

شرط‌ها:
- \`stat\`: مقدار ویژگی بازیکن
- \`health\`: جان فعلی
- \`flag\`: پرچم منطقی یا متنی
- \`item\`: تعداد آیتم در کوله‌پشتی
- \`quest\`: وضعیت مأموریت

عملگرها: \`==\`، \`=\`، \`!=\`، \`>\`، \`<\`، \`>=\` و \`<=\`. تمام شرط‌های یک انتخاب باید درست باشند تا آن انتخاب نمایش داده شود.

## ۶. اثرهای انتخاب

اثرها به ترتیب اجرا می‌شوند. اگر یکی از اثرها خطا بدهد، موتور وضعیت را به قبل از انتخاب برمی‌گرداند.

### ویژگی‌ها

\`\`\`json
{"type": "stat", "name": "سکه", "op": "add", "value": 5}
{"type": "stat", "name": "تجربه", "op": "set", "value": 100}
{"type": "stat", "name": "سکه", "op": "subtract", "value": 2}
\`\`\`

### جان

\`\`\`json
{"type": "health", "op": "add", "value": 10}
{"type": "health", "op": "subtract", "value": 25}
{"type": "health", "op": "set", "value": 100}
\`\`\`

جان بین صفر و حداکثر جان محدود می‌شود. رسیدن جان به صفر بازی را پایان می‌دهد.

### آیتم‌ها

\`\`\`json
{"type": "item", "name": "کلید", "action": "add", "count": 1}
{"type": "item", "name": "معجون", "action": "remove", "count": 1}
{"type": "item", "name": "سکه", "action": "set", "count": 20}
\`\`\`

اگر بازیکن آیتم لازم برای مصرف را نداشته باشد، انتخاب اجرا نمی‌شود و هیچ‌یک از اثرهای قبلی آن انتخاب باقی نمی‌مانند.

### پرچم‌ها

\`\`\`json
{"type": "flag", "name": "در_باز_شد", "value": true}
\`\`\`

### مأموریت‌ها

ابتدا مأموریت را در آرایه quests تعریف کن:

\`\`\`json
{"id": "find_key", "title": "پیدا کردن کلید"}
\`\`\`

سپس از اثر استفاده کن:

\`\`\`json
{"type": "quest", "id": "find_key", "action": "start"}
{"type": "quest", "id": "find_key", "action": "complete"}
{"type": "quest", "id": "find_key", "action": "fail"}
\`\`\`

### دفترچه وقایع

\`\`\`json
{"type": "journal", "text": "روی دیوار یک پیام رمزآلود دیدم."}
\`\`\`


## ۷. شخصیت، رسانه و گفتگوی تعاملی

ساختار شخصیت می‌تواند شامل پرتره، ویدیوی پیش‌فرض، صدا، مدل سه‌بعدی و نگاشت حالت‌های چهره باشد:

```json
{
  "id": "guard",
  "name": "نگهبان",
  "portrait": "assets/guard.webp",
  "video": "assets/guard-idle.mp4",
  "voice": "assets/guard-voice.ogg",
  "model": "assets/guard.glb",
  "expressions": {
    "happy": "assets/guard-happy.mp4",
    "angry": "assets/guard-angry.mp4"
  },
  "ai": {
    "enabled": true,
    "model": "gpt-4o-mini",
    "api_base": "https://api.openai.com/v1",
    "system_prompt": "در نقش نگهبان پاسخ بده.",
    "rules": [{"trigger":"سلام","response":"درود، مسافر."}]
  }
}
```

هر خط دیالوگ می‌تواند character، text، expression، video، voice و زمان شروع/پایان کلیپ داشته باشد. اگر ویدیو یا صدا مشخص نشده باشد، رسانهٔ پیش‌فرض شخصیت استفاده می‌شود.

قواعد ai.rules بر اساس وجود عبارت پرسش در پیام اجرا می‌شوند و به API نیاز ندارند. برای پاسخ آزاد، کلید API هنگام اجرای بازی وارد می‌شود و در پروژه ذخیره نمی‌شود. ارائه‌دهنده باید CORS را برای صفحهٔ بازی مجاز کرده باشد.

## ۸. رسانه و رابط بازی

هر صحنه می‌تواند image، video، music، model، button_sound، video_start و video_end داشته باشد. هر انتخاب می‌تواند صدای مستقل sound داشته باشد. عناصر رابط در ui.elements از نوع text، button، name_input یا location هستند و موقعیت و عرض آن‌ها به‌صورت درصدی از صفحه تعیین می‌شود.

## استفاده از موتور در Python

\`\`\`python
from monn import GameEngine, load_project

project = load_project("examples/story_adventure.mongame.json")
game = GameEngine(project)

print(game.scene["title"])
print(game.available_choices())

game.choose("take_card")  # شناسه انتخاب
print(game.snapshot())

game.save("save.json")
game.load("save.json")
\`\`\`

همچنین می‌توان به جای شناسه، متن دقیق انتخاب یا شماره داخلی انتخاب در همان صحنه را به \`choose\` داد.

ساخت خروجی وب از Python:

from monn import load_project, compile_game_to_html

project = load_project("examples/story_adventure.mongame.json")

with open("game.html", "w", encoding="utf-8") as file:
    file.write(html)

## تست و عیب‌یابی

\`\`\`powershell
py -m compileall -q monn monn_cli.py
py -m unittest discover -s tests -v
\`\`\`

در صورت نصب Node.js، تست خودکار ساختار نحوی JavaScript خروجی وب نیز اجرا می‌شود.

خطاهای رایج:
- صحنه شروع پیدا نشد: مقدار meta.start_scene باید با id یک صحنه برابر باشد.
- صحنه مقصد وجود ندارد: target را با شناسه دقیق صحنه تطبیق بده.
- مأموریت تعریف نشده: پیش از اثر quest، مأموریت را در quests اضافه کن.
- انتخاب در دسترس نیست: ممکن است یکی از شرط‌های آن برقرار نباشد.
- آیتم کافی وجود ندارد: تعداد آیتم لازم برای مصرف را بررسی کن.
- ذخیره متعلق به نسخه دیگری است: ذخیره فقط برای همان محتوای پروژه معتبر است؛ تغییر پروژه fingerprint را عوض می‌کند.

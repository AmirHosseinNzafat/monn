## افزونه‌ها و دارایی‌ها
کیت افزونه‌ها برای توسعه ماژول‌های مستقل وجود دارد؛ اما فروشگاه مرکزی، امضای دیجیتال افزونه‌ها و sandbox اجرای افزونه هنوز آماده نیست. افزونه ناشناس را روی پروژه مهم اجرا نکنید.

دارایی‌های آماده باید مجوز روشن داشته باشند. هر دارایی باید نام سازنده، منبع، مجوز و تغییرات را همراه خود نگه دارد. استفاده از محتوای Ren'Py، Twine، ink، GDevelop یا Godot به معنی اجازه کپی کد یا دارایی آن‌ها نیست.

## پشتیبانی و گزارش مشکل
برای گزارش خطا، یک Issue در مخزن GitHub باز کنید و این موارد را بنویسید:
1. نسخه Monn و سیستم‌عامل
2. مراحل بازتولید مشکل
3. نتیجه مورد انتظار و نتیجه واقعی
4. متن خطا و نمونه پروژه کوچک، بدون گذرواژه یا کلید API

تا وقتی تعداد مشارکت‌کنندگان و پاسخ‌گویان کافی شکل نگرفته، زمان پاسخ به Issue تضمین‌شده نیست. از انتشار اطلاعات خصوصی، توکن‌ها، کلیدهای API یا فایل‌های محرمانه خودداری کنید.

## وضعیت صادقانه
Monn یک پروژه مستقل و در حال رشد است. تست خودکار، مستندات و نمونه‌ها ریسک را کمتر می‌کنند؛ اما جایگزین آزمایش روی پروژه واقعی و بازبینی امنیتی مستقل نیستند. قابلیت‌هایی که در نقشه راه «آزمایشی» یا «در دست توسعه» هستند، نباید برای محصول حساس یا تجاری بدون آزمون مستقل انتخاب شوند.
